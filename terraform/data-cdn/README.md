# Infrastructure - Found in Space data CDN

Terraform config that puts a CloudFront distribution in front of the S3 bucket
where Found in Space data assets are stored. This gives browsers HTTP/2
multiplexing, edge caching, and eliminates the HTTP/1.1 six-connection limit
that makes range request-heavy workloads slow.

The public CDN hostname is:

```text
https://data.foundin.space
```

## Prerequisites

- [Terraform](https://developer.hashicorp.com/terraform/install) >= 1.5
- AWS credentials configured (`aws configure` or environment variables)

## Quick start

```bash
cd terraform/data-cdn

# 1. Create your variables file from the example
cp terraform.tfvars.example terraform.tfvars
# Edit terraform.tfvars — set bucket_name, create_bucket, region, etc.

# 2. Initialise and apply
terraform init -backend-config=backend.hcl
terraform plan      # review what will be created
terraform apply     # create the CloudFront distribution
```

After apply, Terraform prints both the stable CDN URL and the underlying
CloudFront domain:

```
data_cdn_base_url = "https://data.foundin.space"
octree_base_url = "https://d1234abcdef8.cloudfront.net"
```

Use the stable URL as the base URL for data files, e.g.:

```
https://data.foundin.space/c56103e6-ad4c-41f9-be06-048b48ec632b/stars.octree
```

## Edge time API

The distribution exposes an uncached time endpoint generated by a CloudFront
Function at the viewer edge:

```text
GET https://data.foundin.space/api/v1/time
```

The response reports the function invocation start time in Unix milliseconds
and ISO 8601 form:

```json
{
  "unixTimeMs": 1786550400000,
  "iso8601": "2026-08-12T16:00:00.000Z"
}
```

Responses include cross-origin access and resource-timing headers for browser
clients and `Cache-Control: no-store`. The dedicated cache behavior means the
function is not invoked for data asset requests.

## Approximate location API

The distribution also exposes an uncached endpoint using CloudFront's built-in
IP geolocation:

```text
GET https://data.foundin.space/api/v1/location
```

Example response:

```json
{
  "available": true,
  "precision": "ip",
  "latitude": 52.3676,
  "longitude": 4.9041,
  "city": "Amsterdam",
  "region": "North Holland",
  "countryName": "Netherlands",
  "countryCode": "NL",
  "postalCode": "1012",
  "timezone": "Europe/Amsterdam"
}
```

CloudFront derives this approximate location from the viewer's network address.
It can resolve to a city centroid, ISP gateway, or VPN exit and must not be used
as a substitute for GPS when calculating local eclipse contacts. Fields that
CloudFront cannot determine are returned as `null`; `available` is `false` when
latitude or longitude is unavailable, including requests originating from some
AWS network addresses.

The origin request policy forwards only the eight required viewer-location
headers. It deliberately excludes `CloudFront-Viewer-Address` and ASN, and the
Lambda function does not log request data. The private Lambda Function URL can
only be invoked by this CloudFront distribution using Origin Access Control.
Responses support `GET`, `HEAD`, and `OPTIONS`, include browser CORS headers,
and are marked `Cache-Control: no-store`.

Run the focused function contract tests with:

```bash
node --test terraform/data-cdn/functions/location-api-v1.test.mjs
```

## Existing vs new bucket

Set `create_bucket = false` (the default) to use an existing S3 bucket.
Terraform reads the bucket as a data source and adds a bucket policy granting
CloudFront read access via Origin Access Control.

Set `create_bucket = true` to have Terraform create the bucket. It will also
configure public access blocking and CORS.

## What gets created

| Resource | Purpose |
|----------|---------|
| CloudFront distribution | HTTP/2+3 CDN, edge caching |
| ACM certificate | TLS certificate for `data.foundin.space` in `us-east-1` |
| Origin Access Control | Lets CloudFront read private S3 objects |
| S3 bucket policy | Grants CloudFront read access |
| Route 53 records | Certificate validation plus `data.foundin.space` A/AAAA aliases |
| Cache policy | Includes `Range` header in cache key so range requests cache correctly |
| Response headers policy | CORS headers for browser range requests |
| CloudFront Function | Returns edge invocation time from `/api/v1/time` |
| Time API cache policy | Disables caching for time responses |
| Lambda Function URL and OAC | Privately serves `/api/v1/location` through CloudFront |
| Location origin request policy | Forwards only non-IP CloudFront viewer-location headers |
| Location response policy | Adds CORS, no-store, and browser security headers |
| CloudWatch log group | Retains Lambda platform logs for 14 days; the function logs no request data |
| S3 bucket *(optional)* | Only when `create_bucket = true` |

## Cache invalidation

Octree files are addressed by dataset UUID, so new builds get new paths
and don't need invalidation. If you do need to invalidate:

```bash
aws cloudfront create-invalidation \
  --distribution-id $(terraform output -raw cloudfront_distribution_id) \
  --paths "/*"
```

## Destroying

```bash
terraform destroy
```

This removes the CloudFront distribution, policies, and OAC. If
`create_bucket = true`, it also removes the S3 bucket (which must be empty).
